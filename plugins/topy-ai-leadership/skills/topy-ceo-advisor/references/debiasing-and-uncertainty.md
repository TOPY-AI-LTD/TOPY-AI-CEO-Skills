# Debiasing and Uncertainty

Use this reference when the answer depends on incomplete evidence, strong opinions, or hidden assumptions.

## Why this matters

The biggest decision errors usually come from:

- anchoring on a convenient number
- defending past spend
- asking only for confirming evidence
- mistaking confidence for accuracy
- treating one vivid story as a data set

## Bias scan

Check for these failure modes:

| Bias | Ask yourself | Typical fix |
|---|---|---|
| Anchoring | What number am I already stuck on? | Estimate independently first |
| Confirmation | What evidence would change my mind? | Search for the opposite case |
| Sunk cost | Would I fund this today from zero? | Ignore past spend in the decision |
| Availability | Am I reacting to the latest vivid story? | Use base rates |
| Overconfidence | How often have I been right on similar calls? | Widen the range |
| Status quo | Am I defending inertia? | Run a clean-sheet test |
| Framing | Would the decision change if phrased differently? | Reframe gains and losses |
| Groupthink | Has anyone meaningfully dissented? | Assign a red team |
| Planning fallacy | What happened on similar projects before? | Use reference classes |

## Core techniques

### Pre-mortem

Treat the decision as if it failed badly, then ask why. Use the list of failure modes to create mitigations before committing.

### Red team / steel man

Have one person or one pass build the strongest possible argument against the preferred option. The goal is to make the case hard to dismiss, not easy to win.

### First principles

Strip the problem down to what is actually true, not what is usually said. Rebuild the answer from those facts.

### Reference class forecasting

Ask what happened to similar projects, similar markets, or similar decisions. Start from the base rate and then adjust cautiously.

### Bayesian updating

When evidence is arriving over time, treat each piece as an update to a prior belief, not as a standalone opinion.

### Sensitivity analysis

Change the assumptions that matter most and see whether the answer changes. If it does, the decision is not yet stable.

### 10/10/10 and regret minimization

Use them for irreversible or life-changing choices when the numbers do not settle the question.

## Evidence handling

- separate facts from interpretation
- grade evidence by quality and relevance
- do not double count correlated evidence
- use ranges instead of fake precision
- explicitly name the assumption with the biggest effect

## Decision by uncertainty level

| Situation | Minimum treatment |
|---|---|
| Reversible experiment | quick bias scan |
| High-stakes strategic bet | full scan plus pre-mortem |
| Executive transition or crisis | bias check after stabilization |
| Evidence-driven decision | Bayesian update plus sensitivity analysis |

## Output checklist

1. What do we know?
2. What do we not know?
3. What evidence would change the answer?
4. What assumption is doing the most work?
5. What is the adjusted confidence after the bias check?
